Reports a Jinja use of a variable that has no runtime default and is not guarded (ANS-V003), for example bearer_token = "{{ alloy_tenant_api_key }}" in a role template when the role's defaults/ do not set alloy_tenant_api_key and no {% if alloy_tenant_api_key is defined and alloy_tenant_api_key %} surrounds it.

Templates, role task and handler files, role defaults//vars/ files and playbook tasks are checked. A use is guarded by x is defined (also inside and, or, not and {% if %}/{% elif %}/{% else %} branches), | default(…) or | d(…), … if x is defined else …, a condition that is false while x is undefined ({% if x | default(false) %}, x | default('') | length > 0), or such a when: on the task that runs it, its blocks, its include chain or the role's entry in the play. {% if x %} is not a guard: ansible-core fails on an undefined x there.

The severity depends on every environment, host and play that runs the use, whatever context is selected:

  • Error when some reachable host has no definition in any layer and runs the use unconditionally: the message names the environment and the hosts where rendering certainly fails.
  • Warning when such a host runs the use only under a condition (a when, a loop over a variable, a handler, an {% if %} branch, a template chosen by a variable): it fails there whenever it runs.
  • Warning when every host defines the variable today only through the inventory (it works only because each environment sets it, while the role's argument spec says it is optional), or when no play applies the role.

Variables the argument spec marks required: true are left to ANS-P003. A spec default: is documentation only: ansible-core never sets the variable from it. | mandatory uses are reported only with a host that certainly lacks the value. The root setting "Unguarded optional variables without a default are always errors" turns every warning into an error. Quick fixes wrap the statement in an is defined guard, append | default(''), add when: x is defined to the task, or add the variable to the role's defaults/main.yml and its argument spec.
