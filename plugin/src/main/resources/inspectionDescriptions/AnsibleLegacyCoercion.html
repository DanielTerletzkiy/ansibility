Reports values that rely on ansible-core's legacy conversions: a string (split on commas) or a number (wrapped) for a list, a JSON or k=v string for a dict.

Example (ANS-T014):

web_backends: app1,app2     # documented: list, elements: str

A string that cannot become the documented items (a comma string for a list of dicts) is rejected instead, and reported by Value rejected by ansible-core.

Checked: role defaults/ and vars/ (against the role's own meta/argument_specs.yml), group_vars/host_vars files, inline inventory vars, play, block and task vars:, include_role vars and role parameters, and molecule inventories (against every spec of the same root that declares the variable). Templated values and vault values are not judged here.

The message names the role whose spec is violated and says what the root's target ansible-core would do. When no play of the root applies that role, the message says its spec may be stale. The severity follows the root's Ansibility strictness settings (preset, "Require a reachable play for red"). Suppress a finding with # noinspection AnsibleLegacyCoercion on the line above the key, or with #file: noinspection AnsibleLegacyCoercion.
