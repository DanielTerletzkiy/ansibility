Reports module options that the module's documentation for the root's target ansible-core does not list (ANS-M001). ansible-core fails such a task: modules reject unknown parameters (Unsupported parameters for (ansible.builtin.copy) module: dst) and action plugins and includes reject unknown options (Invalid options for ansible.builtin.assert: vars).

Aliases count as documented. Not reported:

  • free-form modules (command, shell, raw, script, meta) and modules that accept arbitrary keys (set_fact, add_host);
  • arguments that come from a template (args: "{{ copy_args }}", a templated module value);
  • action plugins that ignore or hand on unknown arguments (fetch, gather_facts, package, service), and the options the template action hands to copy;
  • modules that no documentation source knows.

Options from args: and k=v words are checked like the module mapping. When the documentation comes from another ansible-core line than the target, the finding is at most a warning (or hidden, as set per root).

Quick fixes: Move '<key>' to task level for a task keyword written among the options, for example 

- ansible.builtin.assert:
    that: db_one | length == 1
    vars:
      db_one: "{{ ... }}"
where vars: belongs to the task; and Rename to '<option>' for a misspelt option.
