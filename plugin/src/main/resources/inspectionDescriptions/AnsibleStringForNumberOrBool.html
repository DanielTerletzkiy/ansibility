Reports a quoted string for an int, float or bool option. ansible-core converts it, but the role receives the string, and on ansible-core 2.19 and later a string in when: fails.

Quick fix: unquote the value.

Example (ANS-T016):

haproxy_servers:
  - name: web1
    ip: 192.0.2.10
    port: "444"

Checked: role defaults/ and vars/ (against the role's own meta/argument_specs.yml), group_vars/host_vars files, inline inventory vars, play, block and task vars:, include_role vars and role parameters, and molecule inventories (against every spec of the same root that declares the variable). Templated values and vault values are not judged here.

The message names the role whose spec is violated and says what the root's target ansible-core would do. When no play of the root applies that role, the message says its spec may be stale. The severity follows the root's Ansibility strictness settings (preset, "Require a reachable play for red"). Suppress a finding with # noinspection AnsibleStringForNumberOrBool on the line above the key, or with #file: noinspection AnsibleStringForNumberOrBool.
