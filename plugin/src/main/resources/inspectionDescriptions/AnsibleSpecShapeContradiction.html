Reports a list or dict where the spec documents str or path (or elements: str). ansible-core stringifies it into its Python representation, which is never what the role means.

When the items are mappings and tasks read attributes of the loop item, the message lists them, and Update spec from usage changes the spec to elements: dict with matching options.

Example (ANS-T010):

admin_users:             # documented: list, elements: str
  - name: alice
    key_file: files/keys/alice.pub

Checked: role defaults/ and vars/ (against the role's own meta/argument_specs.yml), group_vars/host_vars files, inline inventory vars, play, block and task vars:, include_role vars and role parameters, and molecule inventories (against every spec of the same root that declares the variable). Templated values and vault values are not judged here.

The message names the role whose spec is violated and says what the root's target ansible-core would do. When no play of the root applies that role, the message says its spec may be stale. The severity follows the root's Ansibility strictness settings (preset, "Require a reachable play for red"). Suppress a finding with # noinspection AnsibleSpecShapeContradiction on the line above the key, or with #file: noinspection AnsibleSpecShapeContradiction.
