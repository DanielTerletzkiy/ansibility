Reports keys that ansible-core fails to load (ANS-K002):

  • a key of a play, block, import_playbook entry or loop_control that is not one of its keywords for the target version ('retries' is not a valid attribute for a Block);
  • a second action key in a task: a typo such as become_usr: root next to ansible.builtin.file: is read as a second module (conflicting action statements: ansible.builtin.file, become_usr);
  • a keyword that the dynamic includes include_tasks and include_role do not accept, such as become or delegate_to (use apply: or a block).

Keys of a role entry that are not keywords are role parameters and are never reported. A with_<name> key whose lookup the bundled documentation does not list is not reported either: the lookup may be a plugin of the project, and otherwise it is a module option (with_dependencies of community.general.jenkins_plugin). With invalid_task_attribute_failed = False in ansible.cfg, task keys ansible-core then only warns about are warnings. The quick fix Rename to '<keyword>' picks the nearest keyword.
