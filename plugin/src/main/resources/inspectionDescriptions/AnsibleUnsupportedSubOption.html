Reports keys inside a dict, or inside the items of a list of dicts, whose spec documents options but not this key. ansible-core rejects unknown keys at nested levels (unknown top-level variables are never checked).

Quick fixes: remove the key, or add it as a sub-option to the role's meta/argument_specs.yml (same root only; the type is inferred from the value; the preview shows the spec change).

Example (ANS-T002):

app_clients:
  - client_id: demo-app
    extra_scopes:
      - offline_access

Checked: role defaults/ and vars/ (against the role's own meta/argument_specs.yml), group_vars/host_vars files, inline inventory vars, play, block and task vars:, include_role vars and role parameters, and molecule inventories (against every spec of the same root that declares the variable). Templated values and vault values are not judged here.

The message names the role whose spec is violated and says what the root's target ansible-core would do. When no play of the root applies that role, the message says its spec may be stale. The severity follows the root's Ansibility strictness settings (preset, "Require a reachable play for red"). Suppress a finding with # noinspection AnsibleUnsupportedSubOption on the line above the key, or with #file: noinspection AnsibleUnsupportedSubOption.
