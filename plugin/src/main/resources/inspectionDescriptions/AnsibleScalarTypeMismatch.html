Reports a YAML scalar of another type for an int, float or bool option: an int for a bool, a float or bool for an int, a bool for a float. An int for a float is fine (it only widens).

Quick fix: replace with the literal ansible-core converts it to.

Example (ANS-T013):

haproxy_apply_kernel_params: 1     # documented: bool

Checked: role defaults/ and vars/ (against the role's own meta/argument_specs.yml), group_vars/host_vars files, inline inventory vars, play, block and task vars:, include_role vars and role parameters, and molecule inventories (against every spec of the same root that declares the variable). Templated values and vault values are not judged here.

The message names the role whose spec is violated and says what the root's target ansible-core would do. When no play of the root applies that role, the message says its spec may be stale. The severity follows the root's Ansibility strictness settings (preset, "Require a reachable play for red"). Suppress a finding with # noinspection AnsibleScalarTypeMismatch on the line above the key, or with #file: noinspection AnsibleScalarTypeMismatch.
