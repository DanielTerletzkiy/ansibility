Reports module option values that ansible-core rejects when it validates the module arguments, using a port of its own argument spec validation for the root's target version:

  • ANS-T001: the type check fails, for example force: maybe for a bool option or a list for an int;
  • ANS-T002: an unknown key inside an option that documents sub-options;
  • ANS-T003: a required sub-option is missing;
  • ANS-T004: a value outside choices after coercion, for example state: absentx under ansible.builtin.file (follow_redirects: false for uri passes through the boolean rescue);
  • ANS-T005: null for a required or defaulted option whose type check rejects it.

Templated values, vault values and raw options such as mode are not judged. Action plugins that read some options themselves (copy's force, assert, fetch) are checked against what they really validate. These findings are always errors; with documentation from another ansible-core line than the target they are at most warnings. The quick fix Replace with '<choice>' picks the nearest documented choice.
