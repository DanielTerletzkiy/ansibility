Reports null for an option that is required or has a spec default. ansible-core type-checks such a None and rejects it; up to 2.19.0 that includes str options (check_type_str(None) raises).

Example (ANS-T005):

app_clients:
  - client_id: demo-app
    secret: null      # required str

Checked: role defaults/ and vars/ (against the role's own meta/argument_specs.yml), group_vars/host_vars files, inline inventory vars, play, block and task vars:, include_role vars and role parameters, and molecule inventories (against every spec of the same root that declares the variable). Templated values and vault values are not judged here.

The message names the role whose spec is violated and says what the root's target ansible-core would do. When no play of the root applies that role, the message says its spec may be stale. The severity follows the root's Ansibility strictness settings (preset, "Require a reachable play for red"). Suppress a finding with # noinspection AnsibleNullForTypedOption on the line above the key, or with #file: noinspection AnsibleNullForTypedOption.
