Reports a task that writes a secret into a file other users of the host can read (ANS-V113). The tasks checked are template, copy, lineinfile, blockinfile and ini_file (short names, ansible.builtin.* and community.general.ini_file).

The file gets a secret when the template, or the content, line, block or value of the task, uses a vaulted variable: a !vault value, a vault_* name, a variable defined in a vault file (vault.yml), or a variable whose value uses one, such as db_password: "{{ vault_db_password }}" (followed up to three steps). A copy of a vault-encrypted file counts too, unless it sets decrypt: false, and so does any of these tasks with no_log: true.

Others can read the file when its mode gives them the read permission (0644, "0o644", o+r, u=rw,g=r,o=r; an unquoted 644 is the decimal number 644, which also grants others read), or when there is no mode and the task creates the file: a new file gets the default, usually 0644. Group-only modes (0640, u=rw,g=r,o=), modes that give others write or execute only (0711), templated modes, preserve and relative modes that leave others alone (u+rw) are not reported. Nor is a missing mode when the arguments are templated, while the project uses module_defaults, which may supply it, or when the task only changes an existing file, which keeps its mode: lineinfile and blockinfile without create: true, ini_file with create: false.

- name: Database credentials
  ansible.builtin.template:
    src: db.conf.j2
    dest: /etc/app/db.conf
    mode: "0640"

Quick fixes: Set mode to 0600 and Set mode to 0640 write a quoted mode (an anchor or tag on it stays, and an alias such as mode: *m is replaced), or add a mode line to the task's arguments, which also overrides a mode merged in with <<. Nothing is decrypted: only variable names, value shapes and vault headers are read.
