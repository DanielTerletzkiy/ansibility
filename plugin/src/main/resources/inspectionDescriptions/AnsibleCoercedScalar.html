Reports a YAML number, boolean or date where the spec documents str or path. ansible-core converts it with str(), so 3.10 arrives as '3.1' and yes as 'True'; the role itself still sees the original value.

Quick fix: quote the value as written.

Example (ANS-T011):

haproxy_backports_version: 3.2     # documented: str

Checked: role defaults/ and vars/ (against the role's own meta/argument_specs.yml), group_vars/host_vars files, inline inventory vars, play, block and task vars:, include_role vars and role parameters, and molecule inventories (against every spec of the same root that declares the variable). Templated values and vault values are not judged here.

The message names the role whose spec is violated and says what the root's target ansible-core would do. When no play of the root applies that role, the message says its spec may be stale. The severity follows the root's Ansibility strictness settings (preset, "Require a reachable play for red"). Suppress a finding with # noinspection AnsibleCoercedScalar on the line above the key, or with #file: noinspection AnsibleCoercedScalar.
