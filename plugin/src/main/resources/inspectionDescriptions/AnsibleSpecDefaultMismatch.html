ANS-S003. Reports an argument_specs default: that differs from the role default in defaults/. ansible-core never applies a documented default: the role's validation task checks a copy and returns only errors, so the variable always comes from the role defaults, and the documentation is wrong.

The role default is the value Ansible loads: the first of defaults/main.yml, main.yaml, main.json and main (a file or a directory, whose files load in sorted order, the last one winning). Other files of defaults/ load only with defaults_from. Every entry point is checked against the same role default, and dictionary options down their options where the role default is a literal dictionary holding the key.

The values are compared as ansible-test compares documented defaults: both go through the option's type first (a missing type is str), so 1.2 and "1.2" for a str option or yes and true for a bool are the same (the type checks report the spelling on the defaults value). Two spellings YAML types differently ("1.20" and 1.20) and a role default that is a plain {{ other }} followed to a literal are warnings. Other templates, secrets (!vault values, vault_* names, vault files, no_log options and dictionaries with a no_log sub-option), values only a dependency sets and values a whole-file vault loaded later in defaults/ may override are not compared.

# defaults/main.yml
version: 1.2

# meta/argument_specs.yml
argument_specs:
  main:
    options:
      version:
        default: 1.5   # ANS-S003: Ansible uses 1.2

The role default's key gets a hint without highlighting that leads back to the spec. Quick fixes set the documented default to the role default (keeping the spec's quoting where it means the same) or remove it. A value written with a YAML alias or anchor is not copied into the spec. No fix changes defaults/, because that would change what Ansible does.
