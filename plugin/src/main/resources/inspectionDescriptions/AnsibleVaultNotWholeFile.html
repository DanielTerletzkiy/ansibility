Reports files whose vault envelope Ansible does not see (ANS-V107). Ansible decrypts a file only when its first 14 bytes are exactly $ANSIBLE_VAULT; when anything comes first, it uses the file as it is:

  • a !vault | line, or key: !vault | in a file Ansible copies or renders (elsewhere it may be a vars file of one variable, which Ansible loads): the form ansible-vault encrypt_string prints for YAML values, saved as a file;
  • a YAML vars file that is one !vault value instead of a mapping;
  • comments, blank lines or --- before the envelope, an indented envelope, a byte order mark (reported first when more comes before the envelope: remove the mark, then convert);
  • an envelope in quotes or inside other text, in files Ansible copies or renders (below files or templates, templates, *.key, *.pem, *.crt, *.vault, *.password).

copy, template, lookup('file') and lookup('unvault') then deliver the envelope text instead of the decrypted content, without an error; as a vars file it fails to load (did not find expected <document start>, or a value that is not a mapping); ansible-vault view refuses it and ansible-vault encrypt would encrypt it a second time. Verified with ansible-core 2.18 and 2.21. Normal key: !vault | values in YAML are not reported.

Quick fix: Convert to whole-file vault removes the tag or the lines before the envelope and its indentation, keeps the payload and the line separator, and is offered only when the result is a well-formed envelope. It needs no password and decrypts nothing; one undo restores the file. A byte order mark is removed with File | File Properties | Remove BOM. Encrypt File skips such files instead of encrypting them again. Messages name lines, never content. Checked in projects with an Ansible root (detached worktrees are not); files outside a root get the default severity. Documentation (Markdown, reStructuredText, AsciiDoc) is checked only below files or templates, and only a complete header ($ANSIBLE_VAULT;1.1;AES256) counts in quotes or other text, so $ANSIBLE_VAULT_PASSWORD_FILE in a script is no envelope.
