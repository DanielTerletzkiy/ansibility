Reports private keys stored in plaintext (ANS-V108). Ansible copies such files to hosts as they are and warns about nothing; whoever has the repository has the key. Checked in every text file of a project with an Ansible root, inside or outside the roots, also inside YAML and JSON values, flattened onto one line, or base64-encoded as a whole (a Kubernetes Secret's data value):

  • Error: a complete unencrypted private key: PEM (RSA, EC, DSA, PKCS#8), OpenSSH without a cipher, PuTTY without encryption, an OpenPGP private key block; also the key after the certificates of a combined .pem file. A vault password file of a root that is committed or staged: it unlocks every vault of the root (a password script or client script, .env.local itself and a vaulted password file are no finding).
  • Warning: a passphrase-protected key (encrypted PKCS#8, a PEM key with an encryption header, OpenSSH or PuTTY with a cipher; the passphrase can be attacked offline); a plaintext file named like a secret without a key Ansibility can read (*.key below files/ssl or files/ssh, *.password below files), unless it holds only password hashes (see below); any of these in a file that is not committed yet.

A key-like file that holds only password hashes is no plaintext secret and is not reported: one hash per line, alone or as name:hash (htpasswd) or a shadow line (a crypt hash may carry the ! of a locked account), ignoring blank lines, in a file of at most 64 lines and 16 KiB. Recognised: crypt hashes ($1$, $apr1$, $5$, $6$, bcrypt $2a$/$2b$/$2x$/ $2y$, yescrypt $y$, $gy$, scrypt $7$, $sha1$, Sun $md5), argon2, PBKDF2 (passlib and Django), passlib $bcrypt-sha256$, Django bcrypt and argon2, MySQL (* and 40 hex digits, caching_sha2_password $A$005$ also in hex), PostgreSQL SCRAM-SHA-256, LDAP and Dovecot schemes ({SSHA}, {SHA}, {SSHA256}, {SSHA512}, {MD5}, {SMD5}, {CRYPT} and {SHA512-CRYPT}, {BLF-CRYPT} … with a crypt hash, {ARGON2ID}). Still reported, because a plaintext secret looks the same: a bare hex string (openssl rand -hex writes passwords like that), PostgreSQL md5 hashes (they log in without the password), traditional DES crypt, and any # comment or other line next to the hashes.

Certificates, public keys, certificate requests, parameters and truncated examples are never reported. Files ignored by the VCS (.gitignore), whole-file vaults, decrypted vault tabs, Ansibility's ignored paths and the allowlist of Settings | Languages & Frameworks | Ansibility | Vault (Molecule's test folders by default) are not checked. A file outside version control (or any file, in an IDE without VCS support) is reported like a committed one, except a vault password file, which is reported only inside a VCS root: committed or staged (error), or neither committed nor ignored (warning).

Quick fixes: Encrypt file encrypts the file in place with Ansibility Vault (Ansible's copy, template and lookup('file') decrypt it); Encrypt value turns a key held in a YAML value into a !vault | value. A committed vault password file has no fix: remove it from git, add it to .gitignore and rekey the vaults. Encrypting does not remove the plaintext from git history: rotate a key that was ever committed. Outside every Ansible root Ansibility Vault cannot encrypt a file, so there the message says to keep the file out of version control instead. Messages name the kind of key, never its content.
